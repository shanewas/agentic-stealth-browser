# v2.5.0 — Real Dashboard Backend Adapters (#444) + status subcommand fix

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task. OpenCode (preferred) or Claude Code for implementer dispatch. Each task: fresh subagent, two-stage review (spec compliance then code quality).

**Goal:** Replace the three thin dashboard backend adapter aliases with genuinely distinct adapter implementations, define an explicit adapter contract, surface backend capabilities in dashboard status, and fix the v2.4.1 `agentic-stealth-browser status` subcommand crash (missing `--headless`/`--session` args). Cut as v2.5.0.

**Architecture:** Extract a `BackendAdapter` Protocol + concrete transport implementations (Playwright-MCP via stdio, Agentic-Stealth-MCP via stdio, CDP-Bridge via WebSocket). Adapters report negotiated capabilities at launch time; dashboard status surfaces them; switching backends records an audit event and rejects unsupported configurations with a backend-specific error. CLI status bug fixed by aligning its subparser with `_cmd_health`'s argument set.

**Tech Stack:** Python 3.11, FastAPI, Pydantic v2, Playwright Python, asyncio, MCP stdio JSON-RPC, CDP WebSocket (via Playwright `connect_over_cdp`).

## Risk Notes

1. **MCP stdio subprocess flakiness in CI** — both M2 and M3 need reliable subprocess teardown. Mitigation: use `asyncio.subprocess.PIPE` + explicit `process.terminate()` in `close()`; tests use `pytest-asyncio` with timeout=10.

2. **Capability matrix drift** — as #445 (recorder) and #446 (control mode) are added, capabilities will expand. Mitigation: `Capability` enum is the single source of truth; new capabilities go in M0, not retrofitted.

3. **v2.4.1 status subcommand fix is technically #459 scope creep** — the issue is closed, but the bug shipped. Either:
   - (a) Bundle in v2.5.0 (my recommendation — 2 lines, prevents 2.4.x confusion)
   - (b) File as a separate issue and defer
   - Decision: bundle unless you object.

4. **Capability gating in M4 may over-constrain** — the test `test_backend_switch_preserves_named_profile` is a stretch goal. If profile-preservation logic turns out to be coupled to capability diff in a non-trivial way, drop the profile-preservation criterion and file a follow-up.
