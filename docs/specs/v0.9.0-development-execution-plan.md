# v0.9.0 Development Execution Plan

Status: Ready for implementation
Target release: v0.9.0
Planning date: 2026-05-23
Primary tracking issue: #376

## 1) Release objective

Ship v0.9.0 as the first fully runnable and observable MCP release for this repository:

- MCP runtime exists and boots from this repo.
- Operators can inspect active browser session behavior through MCP-native tools.
- CI deterministically gates MCP/runtime contracts.
- Docs/commands/module references are internally consistent.

## 2) Scope baseline

This plan executes the approved v0.9.0 spec:

## 6) Definition of ready (per issue)

Before coding starts on each issue:

- API input/output contract written.

## 7) Definition of done (release gates)

Release blocked unless all are true:

1. MCP runtime:
  - documented launch command works.
  - baseline tools respond with stable schema and error envelopes.
2. Observability:
  - tabs/snapshot/timeline available and redacted.
  - pagination/limits enforced.
3. CI:
  - deterministic required pipeline excludes live-network tests.
  - strict marker enforcement active.
4. Compatibility:
  - migration table published.
  - alias/deprecation behavior tested.
5. Docs:
  - no references to missing modules/files.
  - operator “observe running MCP browser” guide published.

## 8) Test strategy

### Required (PR gating)

- MCP contract tests (runtime + tool schemas).
- security tests for observability redaction/path controls.
- deterministic runtime tests (launch args builder and relaunch parity).
- docs link/reference smoke checks (where practical).

### Optional/nightly/manual

- protected-site E2E and live-network suites.

### Guardrails

- `--strict-markers` in required CI.
- explicit marker registry in pytest config.
- coverage gate raised only on deterministic test set.
