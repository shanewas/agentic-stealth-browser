# v0.9.0 Spec: MCP Runtime, Observability, and Contract Hardening

Status: Draft for implementation
Target release: v0.9.0
Proposed release window: 2-3 weeks from kickoff
Owners: Core runtime + DX maintainers

## 1) Why this release

The repository is strong on core stealth/recovery behavior, but there is a critical gap between documented MCP workflows and what is shipped in this repo today.

Key evidence:

- README instructs users to run `python -m production.mcp_server`, but `production/mcp_server.py` is not present.
- CHANGELOG references `stealth-playwright-mcp/mcp_tools.py` and `stealth_mcp.py`, but those files are not present in this repo.
- `production/__init__.py` references `production.agent_orchestrator`, but this module is not present.
- CI currently ignores `tests/test_mcp_contract.py`, so MCP-facing contracts are not merge-gated.
- Browser observability is fragmented: users can run headed mode and screenshots, but there is no first-class MCP/browser introspection bridge for live sessions.

This version closes those gaps and makes MCP operation observable, testable, and supportable.

## 2) Current state findings (repo analysis)

### 2.1 Contract/documentation mismatches

- README MCP section points to non-existent module entrypoint.
- Changelog mentions files not present in this repository.
- Contributing architecture diagram references missing `production/agent_orchestrator.py`.
- CLI naming is mixed (`agentic-stealth-browser` script vs `stealth-browser` program/help text).

### 2.2 Runtime shape

- `AgentBrowser` is feature-rich but monolithic (~1490 LOC), with launch/relaunch behavior duplicated.
- Launch arguments are deduplicated via `set(...)`, which may reorder flags unpredictably.
- `ConnectionPool` currently tracks domain reuse metadata but does not pool actual Playwright contexts end-to-end.

### 2.3 Testing and release gating

- CI enforces only a subset of tests (multiple key files ignored, including MCP contract test).
- Protected-site E2E tests are intentionally flaky/opt-in, but there is no deterministic replacement contract test for MCP tool behavior.
- Coverage gate is low and not focused on MCP contract critical paths.

## 3) Product goals for v0.9.0

1. Ship a real, documented MCP runtime in this repo.
2. Provide first-class observability into active browser sessions (including what URL/page/state the MCP agent is acting on).
3. Make MCP contract behavior deterministic and CI-enforced.
4. Remove doc/release inconsistencies that break user onboarding.

Non-goals:

- Beating all protected-site E2E instability in CI.
- Major stealth-algorithm rewrites.
- Full v1.0 API freeze.

## 4) Scope (Epics)

## Epic A: MCP Runtime in-repo

### Problem

Users cannot reliably run the MCP server from this repo using documented commands.

### Deliverables

- Add `production/mcp_server.py` with a stable entrypoint.
- Expose documented core tools at minimum:
  - `stealth_launch`
  - `stealth_navigate`
  - `stealth_load_cookies`
  - `stealth_set_region`
  - `stealth_scrape`
  - `stealth_status`
  - `stealth_close`
- Wire `mcp_security.default_security_context` into all file/LLM/tool description surfaces.
- Add version/capability endpoint (e.g., `stealth_capabilities`) for MCP clients.

### Acceptance criteria

- `python -m production.mcp_server` starts successfully.
- Tool manifest aligns with README tool table.
- Contract tests validate tool response shape and error shape.
- Security policies are enforced on file inputs.

## Epic B: Browser Observability Bridge (MCP + live browser visibility)

### Problem

Operators cannot clearly inspect what the MCP-driven browser is doing in real time through a supported contract.

### Deliverables

- Add introspection tools:
  - `stealth_tabs_list`: tab id/title/url/current marker
  - `stealth_tab_snapshot`: screenshot + lightweight DOM/title/url metadata
  - `stealth_session_timeline`: recent action/recovery timeline from `AuditLogger`
  - `stealth_debug_report`: normalized debug dump (existing capability surfaced through MCP)
- Add session naming and correlation IDs in tool responses.
- Add optional live mirror mode:
  - periodic snapshots to configured output directory
  - bounded retention and explicit opt-in

### Operator workflow definition

1. Start MCP server.
2. Launch session via `stealth_launch`.
3. Call `stealth_tabs_list` and `stealth_tab_snapshot` to inspect current activity.
4. Use `stealth_session_timeline` for recovery/debug chronology.

### Acceptance criteria

- Operators can inspect active URL/title and latest screenshot without attaching external devtools.
- Snapshot tooling works in both headed and headless modes.
- No sensitive values leak in timeline/snapshot metadata.

## Epic C: Runtime/API hardening and integrity fixes

### Problem

A few core inconsistencies increase support burden and hidden runtime risk.

### Deliverables

- Resolve missing reference in `production/__init__.py` (either implement `agent_orchestrator.py` or remove stale reference).
- Normalize CLI naming and docs (`agentic-stealth-browser` vs `stealth-browser`) with one canonical command and aliases if needed.
- Fix launch arg dedupe ordering (replace `list(set(...))` with stable dedupe preserving precedence).
- Refactor launch/relaunch shared option assembly into a single helper to reduce divergence.
- Clarify `ConnectionPool` behavior (either true context pooling integration or documentation rename if telemetry-only).

### Acceptance criteria

- No docs reference missing modules.
- Launch args are deterministic across runs.
- Rotation relaunch uses the same validated option builder as initial launch.
- Connection pooling behavior is explicit and tested.

## Epic D: Test strategy and CI contract gates

### Problem

Critical MCP and runtime contracts are not currently merge-gated.

### Deliverables

- Split tests into:
  - deterministic contract/unit (required)
  - live protected-site E2E (optional/nightly/manual)
- Re-enable and stabilize `tests/test_mcp_contract.py` in required CI path (or replace with deterministic MCP server contract tests).
- Add explicit marker policy and CI matrix:
  - required: `not e2e and not live_network`
  - optional/nightly: live_network suites
- Increase coverage target for critical packages in steps (e.g., 65 -> 70 in v0.9.0).

### Acceptance criteria

- PR CI fails on MCP contract regressions.
- Required CI does not depend on third-party anti-bot website uptime.
- Marker taxonomy documented in `tests/README.md`.

## Epic E: Docs/release alignment

### Problem

Documentation contains outdated references and version history inconsistencies.

### Deliverables

- Sync README MCP section with actual runtime and commands.
- Sync CHANGELOG links and released versions (currently inconsistent with `v0.8.0` release/tag reality).
- Update CONTRIBUTING architecture tree to reflect real file structure.
- Add “How to observe running MCP browser” guide with concrete workflows:
  - built-in MCP observability tools (primary)
  - headed mode + screenshots (fallback)
  - CDP attach path (only when client supports CDP backend)

### Acceptance criteria

- New users can launch MCP and inspect live state with no missing module errors.
- Changelog/release links match existing tags/releases.
- Docs no longer mention absent modules/files.

## 5) MCP browser observability compatibility notes

This project should explicitly document backend constraints:

- If the host client exposes only an in-app browser backend (no CDP backend), it cannot “attach” to an arbitrary external browser process directly.
- Therefore, v0.9.0’s primary observability path must be MCP-native snapshots/status tools rather than CDP-only workflows.
- If CDP backend is available in the client, an optional `stealth_get_cdp_endpoint` flow can be added later.

## 6) API contracts (new/updated)

### `stealth_tabs_list` response (proposed)

```json
{
  "status": "ok",
  "session": "linkedin-prod-1",
  "tabs": [
    {
      "tab_id": "tab-1",
      "title": "LinkedIn Feed",
      "url": "https://www.linkedin.com/feed/",
      "is_current": true,
      "last_updated_ts": 1760000000.123
    }
  ]
}
```

### `stealth_tab_snapshot` response (proposed)

```json
{
  "status": "ok",
  "session": "linkedin-prod-1",
  "tab_id": "tab-1",
  "title": "LinkedIn Feed",
  "url": "https://www.linkedin.com/feed/",
  "screenshot_path": "/abs/path/.agentic-browser/debug/snap_1760000000.png",
  "dom_summary": {
    "has_captcha_signal": false,
    "has_rate_limit_signal": false
  }
}
```

### Error envelope standardization

All MCP tools should return:

```json
{
  "status": "error",
  "error_code": "MCP_VALIDATION_ERROR",
  "message": "human-readable summary",
  "details": {}
}
```

## 7) Rollout plan

- Update README + CONTRIBUTING for runtime correctness.

Phase 2:

- Implement Epic C cleanup and deterministic launch/relaunch option builder.
- Wire CI required tests for MCP contracts.

Phase 3:

- Final docs sweep and release notes.
- Publish v0.9.0 with migration notes.

## 8) Risks and mitigations

- Risk: Live-site E2E remains flaky.
  - Mitigation: keep live-site tests optional, enforce deterministic contracts in required CI.
- Risk: Snapshot tooling leaks sensitive data.
  - Mitigation: redact via existing `AuditLogger`/security utilities before return.
- Risk: Added MCP surface expands maintenance.
  - Mitigation: strict contract tests + stable error envelope.

## 9) Definition of done for v0.9.0

- MCP runtime is runnable from this repo exactly as documented.
- Operators can inspect active browser state through MCP-native observability tools.
- Required CI validates MCP contracts deterministically.
- No stale/missing-module docs references remain in README/CONTRIBUTING/CHANGELOG.
